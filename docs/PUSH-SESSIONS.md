# Research Push session isolation

Room sessions exist only in memory and are scoped to wallet address, chain and connector identity. A root observer remains mounted outside membership and routing gates so disconnects invalidate room clients even when the messenger is closed. Reloading requires the user to enable rooms again. Room views and joined-room query keys use the session revision, preventing earlier drafts, messages or membership results from appearing under a new connection.

The SDK receives only a guarded signer. Each signing/recovery request checks the actual provider account and chain before and after the call, including when wallet events are missing. Legacy encryption-key RPC calls use the selected connector rather than another injected wallet. Raw SDK clients and decrypted keys are not exposed to UI consumers. Late responses are rejected and uncertain writes are never automatically retried; an already-dispatched Push operation may still finish and must be reconciled against history/membership.

No decrypted keys are written to localStorage. An existing `bittrees.push.pgp.<wallet>` record is retired only after independent signer recovery returns the exact same key. A mismatch or inaccessible store fails closed and preserves the original for recovery. Nothing is bulk-deleted or exported. SDK auto-upgrade is disabled, preserving existing identities. Research room definitions, IDs, membership policy, registry signing envelopes and deployed authority configuration are unchanged. Previously open tabs must reload to receive the new protections. JavaScript cannot guarantee erasure of all previously allocated memory.

Push SDK 1.7.32 is pinned with the reviewed Governance patch: group secrets are decrypted using the current wallet key for each read instead of a global session-key cache, increasing per-message history request/decryption work, and legacy recovery selects the bound provider before considering the injected fallback. `patch-package --error-on-fail` runs during install, build and the real-SDK browser suite. CI installs without lifecycle scripts, then build applies the patch; a missing/inapplicable patch fails the build.

Validation: `yarn test:push-unit`, `yarn test:push-browser`, `yarn test:push-sdk-browser`, existing recovery/registry tests and production build. Session browser tests use synthetic wallet/SDK boundaries; the SDK suite builds the actual patched SDK and uses real PGP/AES with intercepted HTTP. Neither suite grants membership or sends live messages. Real authorized Research-member room history, moderation/action parity and physical wallet/device acceptance remain launch requirements.

The lockfile refreshes the patch tool’s inherited Picomatch2 dependency to2.3.2 for [GHSA-c2c7-rcm5-vvqj](https://github.com/micromatch/picomatch/security/advisories/GHSA-c2c7-rcm5-vvqj). This is not a clean dependency-audit claim: Research’s broader inherited dependency findings require the next hardening increment.
